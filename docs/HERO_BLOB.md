# Анимированная «клякса» в hero

Компонент: `src/components/HeroBackground.astro`. Это видео-заливка из Figma (`2604146_Backgrounds_Abstract_1280x720`, слой с blend = color-burn), подключённая настоящим `<video>`.

## Как устроено

- `src/assets/bg/hero-blob-loop.mp4` — тот же ролик, пересобранный в **бесшовную петлю**: 1280 × 720, 30 к/с, 8 с, H.264, ~1 МБ. `src/assets/bg/hero-blob-poster.webp` — постер (первый кадр петли): виден до старта видео, без JS и при `prefers-reduced-motion`.
- `<video muted loop playsinline>` лежит в слое `.hero-bg`, у него `mix-blend-mode: color-burn` — он смешивается с градиентом hero так же, как видео в Figma. Серый фон ролика (`#e3e3e3`) остаётся в кадре; слой `.hero-bg::before` продолжает этот серый за краями видео (на узких экранах ролик не закрывает hero целиком), поэтому границы кадра не видны.
- Позиция и размер — из макета (hero 1728×1117): слой 2600×1462 (масштаб 2,0317 к видео), центр кадра в `(79,17% − 84 px; 50% + 19 px)`, поворот 0,23°. В CSS: `--k` (px на px видео, `0,11757vw` ⇒ 2,0317 при 1728 px, не меньше 0,9 px), `--ax`, `--ay`.
- Небольшой скрипт в компоненте запускает видео, ставит на паузу вне экрана, в неактивной вкладке и при `prefers-reduced-motion`.

### Зацикливание

Исходный ролик (10 с) не зациклен: начинается бугристой формой, заканчивается гладкой. Поэтому в петле хвост (8–10 с) плавно растворён в начало (0–2 с): для кадров `t < 2 с` кадр = `видео(t + 8)` снизу и `видео(t)` сверху с прозрачностью `t / 2`; остальное — `видео(t)` без изменений. Последний кадр петли (≈ `видео(7,97)`) переходит в первый (`видео(8,0)`) без скачка: разница между ними на уровне разницы соседних кадров. В первых ~2 с видны две накладывающиеся формы — это и есть растворение.

Нативный `loop` браузера на стыке даёт паузу в один кадр (~20 мс); на медленном морфинге она не заметна.

## Как пересобрать петлю (другой ролик/параметры)

Нужен Chromium с WebCodecs (Chrome, Edge, Claude Desktop browser pane). Петля собирается в браузере через `<canvas>` + `VideoEncoder` + `mp4-muxer`, ffmpeg не нужен.

```bash
npm i --no-save mp4-muxer                          # временно, в package.json не попадает
node scripts/hero-loop/serve.mjs "C:/путь/к/исходнику.mp4"
```

Откройте `http://localhost:4400/scripts/hero-loop/enc.html` и в консоли выполните:

```js
await run()        // собирает src/assets/bg/hero-blob-loop.mp4 (~1,5 мин)
await poster()     // сохраняет hero-blob-poster.png — первый кадр петли
```

Параметры `run({ loopSec: 8, xfadeSec: 2, bitrate: 3.5e6 })`: длина петли, длина растворения (тоже секунды хвоста исходника, поэтому `loopSec + xfadeSec` не больше длины ролика), битрейт (H.264-кодек браузера обычно выдаёт меньше заданного — 3,5 Мбит/с даёт ~1 МБ без бэндинга на плавных градиентах). `poster.png` сконвертируйте в webp (например, через `sharp`) и положите как `hero-blob-poster.webp`.

Если у ролика другие размер или частота кадров — поменяйте `W`, `H`, `FPS` в `scripts/hero-loop/enc.html` и в компоненте: `1280` / `720` в `calc(1280 * var(--k))` и смещениях `640` / `360` (половина размера).

Компромисс: видео декодируется на каждом кадре со смешиванием `color-burn` по площади hero — на слабых устройствах это нагрузка на GPU; при жалобах можно отключать видео на мобильных (оставлять постер).
