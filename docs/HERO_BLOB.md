# Анимированная «клякса» в hero

Компонент: `src/components/HeroBackground.astro`. Это повтор видео-заливки из Figma (`2604146_Backgrounds_Abstract_1280x720`, 10 с, слой с blend = color-burn) **без `<video>`**: покадровая CSS-анимация по спрайту.

## Как устроено

- `src/assets/bg/hero-blob-sprite.webp` — 120 кадров (15 к/с × 8 с), сетка 12 × 10, ячейка 350 × 335 px (≈ 4200 × 3350, ~0,85 МБ). Кадры вырезаны из ролика по рамке блоба (`x=356, y=76, 584×558` в координатах видео 1280×720). Серый фон ролика (`#e3e3e3`) сделан прозрачным.
- Серый фон вернул слой `.hero-bg::before` (`#e3e3e3` + `mix-blend-mode: color-burn`), сам блоб — тоже `color-burn`. Итоговый цвет как в Figma; цвета кадров не менялись.
- Позиция и размер — из макета (hero 1728×1117): слой 2600×1462 (масштаб 2,0317 к видео), центр кадра в `(79,17% − 84 px; 50% + 19 px)`, поворот 0,23°. В CSS: `--k` (px на px видео, 0,11757vw ⇒ 2,0317 при 1728 px, не меньше 0,9 px), `--ax`, `--ay`.

### Зацикливание

Ролик не зациклен (начинается бугристой формой, заканчивается гладкой). Поэтому петля в спрайте — **8 с**, а хвост ролика (8–10 с) плавно растворён в его начало (0–2 с): для кадров `t < 2 с` кадр = `видео(t + 8)` → `видео(t)` с линейным нарастанием прозрачности. Кадр 119 (≈ `видео(7,93)`) переходит в кадр 0 (`видео(8,0)`) без скачка. В первых ~30 кадрах видны две накладывающиеся формы — это и есть растворение.

### Плавность

`steps()` листает кадры только с частотой 15 к/с, что на медленной морфинг-анимации выглядело дёргано. Поэтому:

- под `.hero-bg__frame--cur` показан текущий кадр (`blob-x` 0,8 с × 12 шагов на строку, `blob-y` 8 с × 10 шагов);
- сверху лежит `.hero-bg__frame--next` — **следующий** кадр (те же анимации со сдвигом `animation-delay: −1 кадр`), у которого `blob-mix` линейно поднимает `opacity` 0 → 1 за длительность кадра. Получается покадровая интерполяция (cross-dissolve);
- оба слоя собраны в группу `.hero-bg__blob` (`isolation: isolate`), и `color-burn` применяется ко всей группе, а не к каждому кадру отдельно.

`prefers-reduced-motion` — статичный первый кадр.

## Как пересобрать спрайт (другой ролик/качество)

Понадобится ролик и любой способ отдать его браузеру с CORS (например, временный статический сервер с POST-эндпоинтом для сохранения файла). Спрайт собирается в браузере через `<canvas>`:

1. Загрузить `<video crossOrigin="anonymous" muted>`; для кадра `i` (`t = i / FPS`) — `video.currentTime = t`, дождаться `seeked`.
2. `ctx.drawImage(video, X0, Y0, CW, CH, 0, 0, cellW, cellH)` (рамка блоба + масштаб) и для каждого пикселя: `a = clamp((max(|r−227|, |g−227|, |b−227|) − 6) / 40)`; для `0 < a < 1` цвет «очищается» от серого: `c = (c − (1 − a)·227) / a`; `alpha = a`.
3. Для `t < XF` (2 с) — два таких RGBA-кадра, `видео(t + P)` (P = 8 с) и `видео(t)`, накладываются друг на друга с `globalAlpha = t / XF` (растворение делается **после** вырезания фона, иначе по краям остаётся серая грязь).
4. Кадр `i` кладётся в ячейку `(i % COLS, floor(i / COLS))` общего холста; `canvas.toBlob(…, 'image/webp', 0.85)` → сохранить в `src/assets/bg/hero-blob-sprite.webp`.
5. Если меняются `COLS/ROWS`, размер рамки (`CW/CH`), FPS или длительность петли — обновить в компоненте `--cols`, `--rows`, `--cw`, `--ch`, число шагов и длительности (`0.8s` = время одной строки, `8s` = вся петля, `--frame` = длительность кадра), а также смещение `284 * var(--k)` = (центр видео − (X0, Y0)).

Компромиссы: спрайт в памяти занимает ~55 МБ (≈ 14 Мпикс); слои анимации перерисовываются на главном потоке 15 раз в секунду.
